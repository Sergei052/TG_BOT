# Telegram-бот: квизы по Гарри Поттеру + ИИ-помощник + админ-панель

Многофункциональный Telegram-бот на Python (python-telegram-bot, PostgreSQL, GigaChat):

- 🏰 квиз «Какой ты факультет Хогвартса» и 🪄 квиз «На какого персонажа ты похож»;
- 🤖 ИИ-помощник на GigaChat с памятью о пользователе и историей диалога;
- 🛠 админ-панель прямо в Telegram: статистика, пользователи, бан, обезличивание, рассылка, настройки, диагностика БД, экспорт;
- 👤 расширенный профиль пользователя и журнал действий в PostgreSQL;
- 🔒 команда `/privacy`: пользователь сам удаляет свои персональные данные (остаётся только обезличенная статистика).

## Возможности

### Для пользователей

| Команда | Что делает |
|---|---|
| `/start` | Приветствие и главное меню |
| `/menu` | Главное меню кнопками |
| `/quiz` | Квиз: твой факультет |
| `/hogwarts` | Квиз: твой персонаж |
| `/ai вопрос` | Вопрос ИИ-помощнику |
| `/profile` | Что бот помнит о вас (предпочтения для ИИ) |
| `/myresults` | Результаты ваших квизов |
| `/forget` | Удалить свою память и историю чата с ИИ |
| `/privacy` | Какие данные хранит бот + удаление персональных данных |
| `/time`, `/random` | Время; случайное число и цвет |
| `/cancel` | Отменить текущее действие |

В `/menu` можно включить **«Режим ИИ»**: тогда достаточно просто писать сообщения, без `/ai`.
В квизах варианты ответов выписаны в тексте вопроса (А, Б, В, Г), а на кнопках стоят буквы.

### Для администратора (`/admin`)

- 📊 **Статистика**: пользователи, активность за 24 часа, новые за 7 дней, Premium, языки, популярные действия, число квизов, число обезличенных записей.
- 👥 **Пользователи**: список по страницам. В карточке: имя, язык, Premium, источник перехода, последние команды; кнопки блокировки, очистки памяти ИИ и обезличивания.
- 📢 **Рассылка**: ввод текста, предпросмотр с числом получателей, подтверждение, отчёт о доставке (в фоне, с учётом лимитов Telegram).
- ⚙️ **Настройки** (применяются сразу, хранятся в БД): включение и выключение ИИ, квизов, эхо-ответов; модель GigaChat; глубина истории; стиль ответов ИИ.
- 🏆 **Итоги квизов**: как часто выпадают факультеты и персонажи.
- 📥 **Экспорт CSV**: выгрузка пользователей (открывается в Excel с кириллицей).
- 🩺 **Диагностика БД**: проверка подключения и схемы, недостающие колонки, размеры таблиц, кнопка «Применить миграции».

Также доступны `/users` и `/broadcast [текст]`.

## Какие данные хранит бот и как их удалить

Только то, что Telegram присылает вместе с сообщением, плюс данные о работе с ботом:

| Данные | Зачем |
|---|---|
| ID, username, имя, фамилия | идентификация, рассылки, админ-панель |
| Язык интерфейса, Telegram Premium, тип чата | статистика аудитории |
| Источник перехода (`?start=...`) | понять, откуда приходят пользователи |
| Время обращений, число обращений, последняя команда | активность |
| Журнал действий: названия команд и кнопок (**без текста сообщений**) | популярность функций |
| Результаты квизов | статистика и `/myresults` |
| История диалога с ИИ и память о предпочтениях | контекст ответов ИИ |

Номер телефона, геолокация и контакты **не собираются**.

**Удаление данных (`/privacy`).** При удалении выполняется *обезличивание*:

- стираются ID, username, имя, фамилия, память ИИ, история диалогов, последняя команда, тип чата;
- остаются без привязки к человеку (под случайным служебным номером): результаты квизов, счётчики и журнал действий, язык, признак Premium, источник перехода, дата регистрации;
- обезличенные записи не участвуют в рассылках, списках пользователей и экспорте, но учитываются в статистике квизов и действий;
- если человек потом снова напишет боту, создаётся новый профиль, никак не связанный со старым;
- заблокированных пользователей обезличить нельзя (иначе они вернулись бы без бана);
- администратор может обезличить пользователя из его карточки в админ-панели.

**Сроки хранения.** История ИИ хранится `MESSAGE_RETENTION_DAYS` дней (по умолчанию 30), журнал действий `EVENTS_RETENTION_DAYS` дней (по умолчанию 90). Значение `0` отключает автоочистку.

**Источники.** Чтобы отслеживать источники, раздавайте ссылки вида `https://t.me/ИМЯ_БОТА?start=instagram`. Источник запоминается только при первом обращении.

Бот хранит персональные данные, поэтому при публичном запуске проверьте требования законодательства вашей аудитории (например, GDPR или 152-ФЗ) и при необходимости добавьте политику конфиденциальности.

## Структура проекта

```
├── main.py             # точка входа, регистрация обработчиков
├── corner.py           # пользовательские обработчики (команды, меню, квизы, ИИ, приватность)
├── admin.py            # админ-панель
├── config.py           # настройки из .env и значения по умолчанию
├── utils.py            # вспомогательные функции
├── db.py               # PostgreSQL: схема, миграции, запросы, диагностика, кэш настроек
├── gigachat_utils.py   # клиент GigaChat и извлечение фактов в память
├── question_answer.py  # данные квизов
├── deploy/
│   ├── update.sh       # обновление бота на сервере
│   └── backup.sh       # резервная копия БД
├── requirements.txt
├── .env.example        # шаблон переменных окружения
└── README.md
```

Поток данных: `main` → `corner` / `admin` → `db`, `gigachat_utils`, `question_answer`.

## Требования

- Python 3.12 или 3.13
- PostgreSQL 12+
- Токен бота от [@BotFather](https://t.me/BotFather)
- Ключ авторизации [GigaChat API](https://developers.sber.ru/docs/ru/gigachat/api/overview) (для ИИ-функций)

## Локальный запуск

1. **Окружение**

```bash
   python -m venv .venv
   # Windows:   .venv\Scripts\activate
   # Linux/Mac: source .venv/bin/activate
   pip install -r requirements.txt
```

2. **База данных**

```sql
   CREATE DATABASE telegram_bot;
```

   Таблицы создаются и обновляются автоматически при каждом запуске (в том числе у баз от старых версий).

3. **Настройка**: скопируйте `.env.example` в `.env` и заполните.

   | Переменная | Описание |
   |---|---|
   | `BOT_TOKEN` | Токен бота из @BotFather |
   | `ADMIN_IDS` | ID администраторов через запятую (свой ID можно узнать у @userinfobot) |
   | `GIGACHAT_CREDENTIALS` | Ключ авторизации GigaChat |
   | `GIGACHAT_SCOPE` | `GIGACHAT_API_PERS` (по умолчанию) |
   | `GIGACHAT_VERIFY_SSL` | `true`, если установлен корневой сертификат Минцифры; иначе `false` |
   | `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD` | Параметры подключения к PostgreSQL |
   | `MESSAGE_RETENTION_DAYS` | Сколько дней хранить историю ИИ-чата (по умолчанию 30, 0 — всегда) |
   | `EVENTS_RETENTION_DAYS` | Сколько дней хранить журнал действий (по умолчанию 90, 0 — всегда) |

4. **Запуск**

```bash
   python main.py
```

   При старте бот создаёт или обновляет таблицы, чистит устаревшие данные, регистрирует команды в меню Telegram и пишет администраторам статус запуска.

## Бесплатный запуск 24/7 (Oracle Cloud Always Free)

Бот работает через long polling и ничего не принимает извне, поэтому открывать порты не нужно. Ему нужна машина, которая не засыпает. Бесплатные тарифы Render засыпают, а у Fly.io и Railway нет постоянного бесплатного плана, поэтому описан вариант с Oracle Cloud Always Free (нужна банковская карта для проверки; деньги не списываются, пока вы остаётесь в бесплатных лимитах). PostgreSQL ставится на ту же машину.

1. **Машина.** `Compute → Instances → Create instance`: образ Ubuntu 24.04, форма `VM.Standard.A1.Flex` (1 OCPU, 6 ГБ). Если нет свободных мощностей («Out of capacity»), возьмите `VM.Standard.E2.1.Micro` (AMD, 1 ГБ). Скачайте SSH-ключ и подключитесь: `ssh -i ключ.key ubuntu@IP`.
2. **Программы** (+ swap для машины с 1 ГБ):

```bash
   sudo apt update && sudo apt install -y python3 python3-venv python3-pip git postgresql
   sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile
   sudo mkswap /swapfile && sudo swapon /swapfile
   echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

3. **База данных:**

```bash
   sudo -u postgres psql -c "CREATE USER botuser WITH PASSWORD 'ПАРОЛЬ';"
   sudo -u postgres psql -c "CREATE DATABASE telegram_bot OWNER botuser;"
```

4. **Код.** Для приватного репозитория создайте на сервере ключ только для чтения и добавьте его в GitHub (`Settings → Deploy keys`, без права записи):

```bash
   ssh-keygen -t ed25519 -f ~/.ssh/github_deploy -N ""
   cat ~/.ssh/github_deploy.pub
   printf 'Host github.com\n  IdentityFile ~/.ssh/github_deploy\n  IdentitiesOnly yes\n' >> ~/.ssh/config
   git clone git@github.com:ЛОГИН/РЕПОЗИТОРИЙ.git ~/bot
```

5. **Настройка и проверка:**

```bash
   cd ~/bot
   python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
   cp .env.example .env && nano .env && chmod 600 .env
   .venv/bin/python main.py      # проверка; остановить: Ctrl+C
```

   Перед запуском на сервере остановите копию бота на своём компьютере: две копии одновременно дают ошибку `Conflict: terminated by other getUpdates request`.

6. **Автозапуск** через systemd. Создайте `/etc/systemd/system/tgbot.service`:

```ini
   [Unit]
   Description=Telegram bot
   After=network-online.target postgresql.service
   Wants=network-online.target

   [Service]
   User=ubuntu
   WorkingDirectory=/home/ubuntu/bot
   ExecStart=/home/ubuntu/bot/.venv/bin/python main.py
   Restart=always
   RestartSec=5
   Environment=PYTHONUNBUFFERED=1

   [Install]
   WantedBy=multi-user.target
```

```bash
   sudo systemctl daemon-reload
   sudo systemctl enable --now tgbot
   sudo systemctl status tgbot
   sudo journalctl -u tgbot -f
```

7. **Обновление бота** после изменений в репозитории: `~/bot/deploy/update.sh`.
8. **Резервные копии.**

```bash
   chmod +x ~/bot/deploy/*.sh
   ( crontab -l 2>/dev/null; echo "0 4 * * * $HOME/bot/deploy/backup.sh" ) | crontab -
```

   Копии лежат в `~/backups` (хранятся 7 последних). Периодически скачивайте их к себе: `scp -i ключ ubuntu@IP:~/backups/ФАЙЛ.sql.gz .`. Восстановление: `gunzip -c ФАЙЛ.sql.gz | sudo -u postgres psql telegram_bot`.

Особенности бесплатного плана Oracle (условия могут меняться, проверяйте актуальные на сайте Oracle): неактивные аккаунты могут быть приостановлены, поэтому заходите в консоль хотя бы раз в месяц; простаивающие машины с минимальной загрузкой CPU могут быть изъяты, поэтому держите резервные копии. Если хотите гарантий, возьмите платный VPS за несколько долларов в месяц: инструкция выше подходит почти без изменений.

## Работа с GitHub

- Репозиторий держите **приватным**. Файл `.env` в `.gitignore`, в репозитории только `.env.example`. Перед каждым коммитом смотрите `git status`.
- Рабочий процесс: правки на компьютере → `git push` → на сервере `~/bot/deploy/update.sh`. Достаточно одной ветки `main`.
- На сервер код попадает через deploy key только для чтения, секреты живут только в `.env` на сервере.
- Если секреты когда-либо попали в репозиторий, перевыпустите их (токен через @BotFather `/revoke`, ключ GigaChat, пароль БД). Историю проще начать с чистого листа в новом репозитории, чем чистить старую.
- Включите двухфакторную аутентификацию на GitHub.
- Необязательно: файл `.github/workflows/ci.yml` с проверкой синтаксиса (`python -m compileall`) при каждом пуше.

## Устройство базы данных

| Таблица | Содержимое |
|---|---|
| `users` | профиль (данные Telegram), память для ИИ, флаги блокировки и обезличивания, источник, последняя команда |
| `user_visits` | счётчик обращений, первая и последняя активность |
| `user_events` | журнал действий (названия команд и кнопок) |
| `quiz_results`, `character_quiz_results` | результаты квизов с очками по каждому варианту |
| `messages` | история диалога с ИИ |
| `settings` | настройки, изменённые из админ-панели |

Все таблицы связаны с `users` через `ON DELETE CASCADE`. Название колонки `griffindor_score` (с опечаткой) сохранено намеренно для совместимости со старыми базами.

## Безопасность

- Файл `.env` **никогда** не коммитьте. Если токен или пароль попали в репозиторий, перевыпустите их.
- Админ-функции проверяются по `ADMIN_IDS` на сервере, а не только скрытием кнопок.
- Заблокированные пользователи отсекаются до любых обработчиков.
- Логи httpx приглушены, чтобы токен бота не попадал в консоль.
- Журнал действий не содержит текста сообщений пользователей.

## Решение проблем

- **В логе `Ошибка БД в …`**: строки после `Traceback` содержат точную причину. Откройте `/admin → 🩺 Диагностика БД`: там видно недостающие колонки, а кнопка «🔧 Применить миграции» повторяет миграции.
- **`Миграция не выполнена … permission denied`**: у пользователя БД нет прав менять таблицы, созданные другим пользователем. Выдайте права или выполните миграции в psql от владельца таблиц.
- **ИИ отвечает «недоступен»**: проверьте `GIGACHAT_CREDENTIALS` и сертификаты (`GIGACHAT_VERIFY_SSL`); подробности в логе.
- **`Conflict: terminated by other getUpdates request`**: бот запущен в двух местах. Остановите лишнюю копию.
- **Бот не отвечает администратору**: проверьте, что ваш ID указан в `ADMIN_IDS`.
- **Статус службы не `active (running)`**: смотрите `sudo journalctl -u tgbot -n 50`.

## Как расширять

- **Новые вопросы или персонажи**: правьте `question_answer.py`. Ключи ответов связаны с колонками `*_score` в БД: для нового персонажа добавьте колонку в `SCHEMA` и `EXPECTED_COLUMNS` в `db.py`.
- **Новый стиль ответов ИИ или модель**: добавьте в `AI_STYLES` / `GIGA_MODELS` в `config.py`, они сразу появятся в админке.
- **Новая команда**: функция в `corner.py` и строка в словаре `commands` в `main.py`.
- **Новый раздел админки**: функция `async def _name(query, context, args)` в `admin.py` и запись в словаре `SECTIONS`.
- **Новое поле профиля**: колонка в `_NEW_COLUMNS` и `EXPECTED_COLUMNS`, поле в `user_to_db` и `get_user_info` в `db.py`; не забудьте `anonymize_user`, если поле персональное.

## Известные ограничения

- Состояние незавершённых квизов и «режима ИИ» хранится в памяти процесса и сбрасывается при перезапуске.
- Бот рассчитан на запуск одним процессом (кэш настроек и банов в памяти).
- Картинки результатов квизов берутся по внешним ссылкам; если ссылка недоступна, отправляется только текст.
- Для каждого запроса открывается отдельное соединение с БД, что достаточно для небольшой и средней нагрузки.
